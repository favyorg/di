# Playground Worker Runtime Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Playground reach `Ready` and execute imported TypeScript reliably on CodeSandbox Nodebox while keeping fast warm runs and isolating each execution from the docs page and persistent runner JavaScript realm.

**Architecture:** Keep the persistent Nodebox/Vite preview as a module compiler and cache, but run warmup and user code in a fresh dedicated module Worker. The runner owns the Worker, validates the existing token protocol, and terminates it on every terminal path; no user module is evaluated in the persistent runner realm.

**Tech Stack:** TypeScript 5.7, React 18, Sandpack 2.20, Nodebox/Vite, Jest 29, Playwright 1.49.

## Global Constraints

- Preserve `/playground/`, all six examples, automatic imports after one second idle, Monaco hover, explicit Run, current UI, bounded output, cancellation, and warm-run behavior.
- Keep the checked-out `@favy/di` sources as the execution and typing source; never install the published package for built-in examples.
- User code must not receive `window`, `document`, `parent`, or `localStorage`, and must never execute in the persistent runner JavaScript realm.
- Create one module Worker for warmup or one Run, validate the existing session/run/event tokens, and call `terminate()` on ready, completion, cancellation, replacement, and failure.
- Treat the random Nodebox preview origin as disposable runtime infrastructure, not as a secrets boundary; the docs origin remains protected by the existing cross-origin Sandpack preview.
- Preserve the 120,000 ms preparation, 10,000 ms commit, 30,000 ms execution, and 1,000 ms cancellation timeouts.
- Never stage `.superpowers/` and never add a Codex/Anthropic co-author trailer.
