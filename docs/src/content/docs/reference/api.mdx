## Common API

### `Module`

`Module` is the default module factory. It uses `withModuleName`, run-scoped
caching, lazy provider resolution, and the identity output transform.

```ts
export declare const Module: DefaultModuleFactory;
```

Create a module in two calls: declare its callback dependencies, then provide a
`PropertyKey` name and callback.

<Editor client:load code={`import { Module, type ModuleLive } from '@favy/di';

type GreetingDeps = {
  subject: string;
} & ModuleLive;

const Greeting = Module<GreetingDeps>()(
  'Greeting',
  ({ subject, Module }) => Module.name.toString() + ': ' + subject,
);
type GreetingLive = typeof Greeting.Live;

console.log(Greeting({ subject: 'hello' })); // "Greeting: hello"
console.log(Greeting.name); // "Greeting"`} />

The dependency map passed to a call must be a non-null object. The runtime
copies its own string and symbol keys into an invocation context; inherited
prototype members are not dependency entries. Consequently, class instances
and custom-prototype objects can be maps when the required dependencies are own
fields.

The default input transform writes the current `{ Module: { name } }` metadata.
Include `ModuleLive` in the callback contract when the callback reads it. The
caller does not supply that generated key.

`Module.flushCache()` clears the factory-wide cache. The default factory uses
`cache: 'run'`, so this normally matters only on a factory created with
`makeModule({ cache: 'module' })`.

### `GenModule`

Creates iterable modules from synchronous generator callbacks:

```ts
GenModule<ExplicitDeps>()(nameOrTag, function* (deps) {
  const service = yield* Dependency;
  return service;
});
```

`ExplicitDeps` may be omitted. The returned `TGenModule` combines explicit
callback requirements with the `Live` contracts of all yielded tags or modules.
Its result is the generator's return type. Passing a tag in place of a name
checks that result against the tag's service contract and uses the tag's key
as the module name. It does not register the implementation as a default.

`yield* Dependency` returns the dependency's service value. Yielding a tag adds
only its service contract; fully bind a provider's dependencies with `.provide()`
before supplying it under `Dependency.name`. Yielding a concrete module also
adds that module's transitive requirements. The composition root always selects
the value or provider to use.

`Tag`, `GenModule`, and `makeGenModule` install the iterable protocol. `.provide()`
preserves it while binding dependencies. Modules from ordinary factories can
consume generator modules through `typeof Foo.Live`, and can supply compatible
implementations under yielded keys, but ordinary modules cannot themselves be
used in `yield*`.

Defaults are `cache: 'run'`, `lazy: true`, and the standard `Module.name`
metadata. The runner accepts synchronous generators, not `async function*`
callbacks or yielded promises. Returned service methods may be async. See the
[runnable generator example](/module/generator/).

### `Tag`

Declares a service key and type independently of an implementation:

```ts
import { Tag, GenModule } from '@favy/di';

const Clock = Tag<{ now(): Date }>()('Clock');
type ClockLive = typeof Clock.Live;

const ClockImpl = GenModule()(Clock, function* () {
  return { now: () => new Date('2026-01-01T09:00:00.000Z') };
});
type ClockImplLive = typeof ClockImpl.Live;

const Main = GenModule()('Main', function* () {
  const clock = yield* Clock;
  return clock.now().toISOString();
});
type MainLive = typeof Main.Live;

console.log(Main({ Clock: ClockImpl })); // 2026-01-01T09:00:00.000Z
```

`Tag<Service>()(key)` returns `TTag<typeof key, Service>`. A tag exposes `name`,
the type-only `Live` marker, and an iterator. It is not callable and has no
`.provide()` method. `typeof Clock.Live` is `{ Clock: { now(): Date } }` and
carries no implementation dependencies. Reading `.Live` at runtime throws.

Identity is the declared `PropertyKey`, not the tag object. Recreating a tag
with the same string key addresses the same service; incompatible contracts
for that key are not detected across declarations. Reuse an exported tag or
choose distinct symbol keys for distinct services. `Tag` rejects the string key
`'Module'`, which is reserved for built-in module metadata. Values and fully bound
providers are supplied through the normal dependency object; a tag alone
never installs an implementation.

### `Live<T>`

Extracts a module's remaining requirements and adds its result under its
declared key. For a concrete module, declare `type FooLive = typeof Foo.Live`
immediately below it. The exported `Live<typeof Foo>` helper computes the same
type and remains useful in generic utilities.

`.Live` is a type-only marker. A TypeScript type query does not evaluate the
property; reading `Foo.Live` at runtime throws.

```ts
export type Live<T> = T extends {
  name: infer K extends PropertyKey;
  [__deps__]: Brand<infer D, infer R>;
}
  ? D & { [P in K]: R }
  : never;
```

`Live` reads the module's existing private type marker directly, so it retains
transitive requirements without recursively expanding the callable and its
`.provide()` method.

<Editor client:load code={`import { Module } from '@favy/di';

const Database = Module<{ url: string }>()('Database', ({ url }) => ({ url }));
type DatabaseLive = typeof Database.Live;

const Repository = Module<DatabaseLive>()(
  'Repository',
  ({ Database }) => Database.url,
);
type RepositoryLive = typeof Repository.Live;

const App = Module<RepositoryLive>()('App', ({ Repository }) => Repository);
type AppLive = typeof App.Live;

console.log(App({ url: 'memory://db', Database, Repository }));
// "memory://db"`} />

### `ModuleLive`

Describes the metadata produced by the default input transform:

```ts
export type ModuleLive = {
  Module: { name: PropertyKey };
};
```

Intersect it into an explicit dependency contract when the callback needs both
application dependencies and the current module name.

## Factory configuration

### `makeModule`

Creates an independent factory. Pass an options object, omit it, or pass an
input transform directly as shorthand.

<details class="api-declaration">
  <summary>Full declaration</summary>

```ts
type Lifecycle = {
  cache?: 'run' | 'module' | 'none';
  lazy?: boolean;
};

type InputFn = (deps: any, name: PropertyKey) => object;
type OutputFn<D = any> = (result: any, deps: D, isRoot: boolean) => any;
type Identity<I> = (<T>(result: T) => T) & ((result: I) => 0);

export declare const makeModule: {
  (
    options?: Lifecycle & {
      transformInput?: undefined | typeof withModuleName;
      transformOutput?: undefined;
    }
  ): DefaultModuleFactory;

  <O extends OutputFn>(
    options: Lifecycle & {
      transformInput?: undefined | typeof withModuleName;
      transformOutput: O;
    }
  ): Factory<object, Named, O>;

  <
    I extends InputFn,
    O extends OutputFn | undefined = undefined
  >(
    options: Lifecycle & {
      transformInput: I & Valid<I>;
      transformOutput?: O;
    }
  ): Factory<
    Domain<I>,
    Added<I>,
    O extends OutputFn ? O : never
  >;

  <D, M, P, I, O>(
    options: MakeOptions<D, M, P, I, O>
  ): Factory<
    D & object,
    P & object,
    transformOutput<I, D & P & object, O> | Identity<I>
  >;

  (transform: typeof withModuleName): DefaultModuleFactory;

  <I extends InputFn>(
    transform: I & Valid<I>
  ): Factory<Domain<I>, Added<I>>;
};
```

</details>

`Factory`, `Named`, `Domain`, `Added`, `Valid`, and `Identity`
above are internal declaration helpers. They infer the input transform's
minimum domain, the fields it adds, and the resulting module call signature;
they are not additional package exports.

| Option            | Default          | Runtime effect                                         |
| ----------------- | ---------------- | ------------------------------------------------------ |
| `transformInput`  | `withModuleName` | Produces the value passed to the callback               |
| `transformOutput` | identity         | Receives a successful callback result                   |
| `cache`           | `'run'`          | Chooses run, factory-wide, or disabled provider caching |
| `lazy`            | `true`           | Resolves providers only when their fields are read      |

<Editor client:load code={`import { makeModule } from '@favy/di';

const SingletonModule = makeModule({ cache: 'module' });

let runs = 0;
const Counter = SingletonModule()('Counter', () => ++runs);
type CounterLive = typeof Counter.Live;

console.log(Counter()); // 1
console.log(Counter()); // 1

SingletonModule.flushCache();
console.log(Counter()); // 2`} />

#### Cache modes

- `'run'` shares a provider result within one root resolution and starts a new
  context for the next root call.
- `'module'` stores results by module name in the factory until
  `flushCache()`.
- `'none'` invokes a provider each time its dependency field is read.

These binding policies belong to the factory of the root module or the module
whose `.provide()` registers that key. Forwarded dependencies keep their
original binding policy. A provider's own `'module'` cache is independent and
can return a cached result even through a `'none'` binding. See
[Mixing factories](/module/cache/#mixing-factories) for an example and flush
behavior.

With `lazy: false`, providers present on the root map are read eagerly before
the module callback. Raw dependency values are never invoked. With
`lazy: true`, object rest/spread can still force reads because it enumerates the
context.

### `MakeOptions<D, M, P, I, O>`

The exported compatibility type for an options object is:

```ts
export type MakeOptions<D, M, P, I, O> = {
  transformInput?: transformInput<D & object, P & object>;
  transformOutput?: transformOutput<I, D & P & object, O>;
  cache?: 'run' | 'module' | 'none';
  lazy?: boolean;
};
```

`M` is retained for source compatibility and is not used by the current
implementation. The actual `makeModule` value uses the overloads above so that
omitted transforms receive their typed runtime defaults and HKT transforms can
replace an ordinary callback or callable shape.

### `makeGenModule`

Creates an independent generator factory with the same callable interface as
`GenModule`:

```ts
export declare const makeGenModule: (options?: {
  cache?: 'run' | 'module' | 'none';
  lazy?: boolean;
}) => typeof GenModule;
```

Options default to `cache: 'run'` and `lazy: true`. The returned factory exposes
`flushCache()`, which clears its own factory-wide module cache. Caching, lazy
resolution, provider replacement, and `.provide()` use the same DI runtime as
ordinary modules. Generator factories can resolve providers created by other
generator or ordinary factories.

The input and output transforms are fixed by this extension; its options only
configure lifecycle behavior. For custom HKT transforms, use `makeModule`.

### `DefaultModuleFactory`

```ts
type Named<N extends PropertyKey = PropertyKey> = {
  Module: { name: N };
};

export type DefaultModuleFactory = Factory<object, Named>;
```

Its public usage is:

```ts
Factory<TransformDomain, AddedInput, OutputTransform?>
  <Deps>()
  (name, callback)
  // => TModule<name, callerDependencies, callbackOrTransformedResult>
```

The first call may omit `Deps`. For the default factory this gives the callback
the generated `Module` metadata and produces a zero-dependency callable.

### `withModuleName`

The default input transform:

```ts
type Generated<N extends PropertyKey = PropertyKey> = {
  Module: { name: N };
};

type Each<D, K extends PropertyKey> = D extends unknown ? Omit<D, K> : never;

export declare const withModuleName: <
  D extends object,
  const N extends PropertyKey
>(
  deps: D,
  name: N
) => Each<D, 'Module'> & Generated<N>;
```

It assigns `{ Module: { name } }` to `deps` and returns that same object. The
type preserves every other input field, preserves union branches, replaces a
previous `Module` field, and keeps a literal string, number, or symbol name for
direct calls.

A custom input transform replaces this behavior unless it explicitly calls
`withModuleName`.

### `transformInput<D, P>`

```ts
export type transformInput<D extends object, P extends object> = <X extends D>(
  deps: X,
  name: PropertyKey
) => X & P;
```

`D` is the minimum input domain and `P` describes added fields. The generic
`X & P` result makes an ordinary transform preserve later dependency fields.
Constrained transforms can be written inline as `<X extends Base>` or assigned
an explicit `transformInput<Base, Added>` annotation. The caller-supplied
portion of a module contract must still satisfy `Base`.

Required inferred additions are removed from the module's caller requirements.
Keys already known on the transform domain remain caller-supplied, while a new
field can still be inferred when the domain has an open index signature. The
compact types intentionally leave unusually ambiguous overlap and union-return
diagnostics to the declared callback contract.

Return an `HKT` marker when a transform intentionally replaces or wraps the
callback input instead of preserving it.

### `transformOutput<I, D, O>`

```ts
export type transformOutput<I, D, O> = (
  result: I,
  deps: D,
  isRoot: boolean
) => O;
```

It receives a successful callback result, that invocation's transformed input,
and whether the call is the root resolution. A custom ordinary output transform
constrains the callback result to `I` and makes the callable return `O`. A
generic identity transform preserves each callback's inferred result. Return an
output `HKT` when the callable type must be computed from its name, callback
result, or remaining dependencies.

The callback runs before `transformOutput`; this hook cannot catch a synchronous
exception that the callback already threw and does not automatically await a
rejected promise.

## Advanced types

### `TModule<K, D, R, C = D>`

`TModule` is the callable returned by an ordinary factory. `D` is the
dependency map still required from the next caller. `C` retains the compatible
full context while `.provide()` binds fields.

The emitted declaration is based on these compact helper types:

<details class="api-declaration">
  <summary>Full declaration</summary>

```ts
declare const __deps__: unique symbol;

type Brand<in D, out R> = {
  result: R;
  accepts: (deps: D) => 0;
};

type Flat<D> = 0 extends 1 & D
  ? D
  : D extends unknown
  ? { [K in keyof D]: D[K] }
  : never;

type ProviderDeps<D> = Flat<D> extends D ? Flat<D> : D;

type Provider<R, D> = ((deps: any) => R) & {
  readonly [__deps__]: Brand<ProviderDeps<D>, R>;
};

type Keys<D> = D extends unknown ? keyof D : never;

type KeylessDeps<D> = {} extends D ? {} : D;

type ModuleDeps<D> = [D] extends [never]
  ? never
  : Keys<D> extends never
  ? KeylessDeps<D>
  : D;

type Required<D> = {
  [K in keyof D]-?: {} extends Pick<D, K> ? never : K;
}[keyof D];

type Value<V> = V extends object
  ? V & { readonly [__deps__]?: never }
  : V;

type Deps<D, C = D> = D extends unknown
  ? {
      [K in keyof D]:
        | Value<D[K]>
        | Provider<D[K], C extends D ? C : never>;
    }
  : never;

type Args<D, C> = Keys<D> extends never
  ? []
  : {} extends D
  ? [deps?: Deps<D, C>]
  : [deps: Deps<D, C>];

type Rest<D, P, Keep = false> = D extends unknown
  ? P extends Partial<Deps<D, Keep extends true ? D : any>>
    ? Keep extends true
      ? D
      : Omit<D, Extract<Required<P>, keyof D>>
    : never
  : never;

type Exact<D, P> = P & Record<Exclude<Keys<P>, Keys<D>>, never>;

export type TModule<K extends PropertyKey, D, R, C = D> = {
  (...args: Args<D, C>): R;
  readonly name: K;
  readonly Live: ModuleDeps<D> & { [P in K]: R };
  readonly [__deps__]: Brand<ModuleDeps<D>, R>;

  provide<const P extends Partial<Deps<D, C>> = {}>(
    ...args: {} extends D ? [deps?: Exact<D, P>] : [deps: Exact<D, P>]
  ): TModule<K, Flat<Rest<D, P>>, R, Rest<C, P, true>>;
};
```

</details>

- A module with no remaining keys takes no argument. A contract compatible
  with `{}` takes an optional dependency object; other contracts require it.
- Every dependency field accepts a final value or a branded module created by
  `Module`/`makeModule` or `GenModule`/`makeGenModule`. Ordinary functions stay
  raw function values. A branded provider is resolved even when the field's
  declared type is broad such as `unknown` or `any`.
- A provider's remaining dependencies must fit a compatible branch of the
  consumer context. `typeof Provider.Live` is the usual way to carry those
  transitive requirements.
- `name` is the readonly declared string, number, or symbol key.
- `Live` exposes the remaining application dependencies and named result for
  `typeof SomeModule.Live` type queries. Runtime reads throw; use a module call
  to obtain its result.
- `.provide()` returns an isolated, still-provider-capable module. Required
  keys present on the partial's type are removed from the next call signature;
  optional keys do not prove that a required dependency was bound. Like the
  module call itself, `.provide()` may omit its map when `D` is compatible with
  `{}`; a contract with required fields still requires an argument.
- Fresh object literals with unknown keys are rejected. Discriminated-union
  calls retain branch-specific required fields, and binding a discriminant can
  narrow the remaining branch. The types deliberately do not attempt exhaustive
  diagnostics for every union-valued or structurally widened partial.
- Bound values take precedence over the root map. Once a bound key is removed
  from the remaining dependency type, TypeScript rejects binding it again with
  `.provide()`. To choose a different value, create another partial from the
  original module. At runtime, if the same key is supplied in successive
  `.provide()` calls (for example, from JavaScript), the later value wins
  without mutating the earlier module.

At runtime, both direct dependency maps and `.provide()` maps may be any
non-null object. Only their own keys are consumed.

<Editor client:load code={`import { Module, type TModule } from '@favy/di';

const Add: TModule<'Add', { left: number; right: number }, number> = Module<{
  left: number;
  right: number;

console.log(ReadyAdd()); // 5
console.log(ReadyAdd.name); // "Add"`} />

### `TGenModule<K, D, R, C = D>`

The iterable extension of `TModule` returned by generator factories. It retains
the call signature, `name`, and `Live` marker, and overrides `.provide()` to
preserve its generator interface:

```ts
export interface TGenModule<K extends PropertyKey, D, R, C = D>
  extends TModule<K, D, R, C> {
  provide<const P extends Partial<Deps<D, C>> = {}>(
    ...args: {} extends D ? [deps?: Exact<D, P>] : [deps: Exact<D, P>]
  ): TGenModule<K, Flat<Rest<D, P>>, R, Rest<C, P, true>>;

  [Symbol.iterator](): Generator<ModuleRequest<K, ModuleDeps<D>, R>, R, unknown>;
}
```

The helper types are those shown under `TModule`. The iterator yields a typed
dependency request and returns the resolved service sent back by the runner.
A type annotation alone does not install this runtime behavior: use
`GenModule` or `makeGenModule` to create iterable modules.

### `TTag<K, Service>`

The non-callable service contract returned by `Tag<Service>()(key)`. It has a
readonly `name: K`, a type-only `Live` marker containing `{ [P in K]: Service }`,
and an iterator returning `Service` while yielding a `ModuleRequest<K, object, Service>`.
It carries no implementation requirements, call signature, or `.provide()`.

Use `Tag` to create the runtime object. A structural type annotation alone does
not create a request accepted by the generator runner.

### `ModuleRequest`

The lightweight type yielded by a tag or generator module's iterator:

```ts
export type ModuleRequest<
  K extends PropertyKey = PropertyKey,
  D = never,
  R = unknown
> = {
  readonly name: K;
  readonly [__deps__]: Brand<D, R>;
} & Iterable<unknown>;
```

It carries the declared key, iterable protocol, and private dependency/result
marker used by `Live`. The request describes a dependency; it is not the resolved service.
Use `yield* SomeTag` or `yield* SomeGenModule` to create one. A plain `{ name }` object is not a
valid module request.

### `HKT`

The nominal base interface for higher-kinded transformations:

```ts
declare const __hkt__: unique symbol;

export interface HKT {
  readonly [__hkt__]: true;
  readonly _NAME: PropertyKey;
  readonly _RESULT?: unknown;
  readonly _DEPS?: unknown;
  readonly _META?: unknown;
  readonly _META2?: unknown;
  readonly type?: unknown;
}
```

Extend it and define `type` in terms of `this['_NAME']`,
`this['_RESULT']`, or the other slots. For an input HKT, `makeModule` supplies
the declared key as `_NAME` and the declared dependency map as `_RESULT` and
`_DEPS`. For an output HKT it supplies the key, callback result, and remaining
dependency map. The symbol marker prevents an ordinary `_NAME` field from being
mistaken for an HKT.

### `Kind<H, NAME, RESULT, DEPS, META, META2>`

Applies concrete slots to an HKT:

```ts
export type Kind<H extends HKT, NAME, RESULT, DEPS, META, META2> = H extends {
  readonly type: unknown;
}
  ? (H & {
      readonly _NAME: NAME;
      readonly _RESULT: RESULT;
      readonly _DEPS: DEPS;
      readonly _META: META;
      readonly _META2: META2;
    })['type']
  : {
      readonly _H: H;
      readonly _NAME: (_: NAME) => void;
      readonly _RESULT: () => RESULT;
      readonly _DEPS: () => DEPS;
      readonly _META: () => META;
      readonly _META2: () => META2;
    };
```

Most applications do not call `Kind` directly. Define an input or output HKT,
return its marker from a transform, and let `makeModule` apply it.
